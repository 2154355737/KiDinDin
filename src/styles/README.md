# KiDinDin 样式约定

`index.css` 是唯一的全局样式入口，由 `src/main.tsx` 导入。入口中的导入顺序属于级联合约，调整顺序前必须确认选择器覆盖关系。

目录职责：

- `foundations/`：浏览器重置、全局基础规则、无障碍和减少动画规则。
- `layout/`：应用外壳、页面框架等跨页面布局。
- `components/`：可被多个页面复用的控件、弹层、导航和工单交互。
- `pages/`：仅属于特定业务页面的样式。
- `themes/`：跨页面主题覆盖和主题变量。

新增样式时遵循以下规则：

1. 优先放入对应组件或页面文件，不在 `index.css` 中直接编写规则。
2. 主题差异优先使用 CSS 变量；组件专属的深色覆盖应留在组件文件附近。
3. Portal 内容必须兼容 `body.theme-dark` 或根节点主题状态，不能只依赖 `.app-shell` 后代选择器。
4. 不新增无说明的 `!important`，也不要通过提高选择器权重掩盖导入顺序问题。
5. 新建模块后按依赖顺序加入 `index.css`，并运行 `npm.cmd run build` 和 `git diff --check`。
